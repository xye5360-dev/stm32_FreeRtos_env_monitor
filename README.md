# 基于 FreeRTOS 的智能环境监测系统

STM32F103C8T6（DShanMCU-F103 开发板）+ FreeRTOS 做的多任务环境监测系统。一块板子上挂了温湿度、光照、超声波、红外几种传感器，实时采集并在 OLED 上显示，数值超标时声光报警，同时每 3 秒通过串口把数据上报给上位机。

主控是 20KB RAM 的 F103C8，资源比较紧，所以整个设计基本围绕"用尽量少的资源把 4 个任务协调好"来做。

## 功能

- 温湿度监测：DHT11 读取，OLED 实时显示。读取失败时显示 `--`，不会拿无效数据去报警
- 光照监测：光敏电阻 + ADC 采集，做过数值反转（详见下面"踩过的坑"），过暗时报警
- 超声波测距：HC-SR04 测距，OLED 显示，无有效回波时显示 `--`
- 红外避障：检测到障碍物立即报警，不做去抖
- 声光报警：超标时蜂鸣器响 3 声、绿灯闪 5 下，恢复正常后自动解除
- 串口上报：每 3 秒发一帧完整数据，可被上位机解析

## 硬件连接

| 外设 | 引脚 | 说明 |
|------|------|------|
| DHT11 温湿度 | PA1 | 单总线，开漏 + 上拉 |
| 光敏电阻 | PA3 | ADC1_IN3 |
| 红外避障 | PB13 | 数字输入，低电平 = 有障碍 |
| 超声波 HC-SR04 | 定时器 + GPIO | 触发 / 回波 |
| 有源蜂鸣器 | PA8 | 低电平有效 |
| 绿色 LED | PC13 | 低电平有效 |
| USART1 | PA9 / PA10 | 115200，8N1，printf 从这里输出 |

注意蜂鸣器和 LED 都是低电平有效的，GPIO 复位后默认就是低电平，所以初始化完外设要主动关掉，不然一上电蜂鸣器就会一直响。

## 任务划分

系统跑 4 个任务，加上一个初始化的主任务：

| 任务 | 周期 | 优先级 | 职责 |
|------|------|--------|------|
| EnvSensorTask | 2000ms | AboveNormal | 读 4 种传感器，拼成一帧数据写入队列 |
| EnvDisplayTask | 1000ms | Normal | 从队列取最新数据刷新 OLED |
| EnvAlarmTask | 500ms | Normal | 判断超标、去抖、声光报警 |
| EnvUARTTask | 3000ms | BelowNormal | 把数据帧 printf 到串口 |

优先级是采集 > 显示 = 报警 > 上报。采集是数据源头又对时序敏感所以放最高，上报晚几秒无所谓放最低。

## 任务间通信

用了 4 种 IPC：

**队列**（`g_xQueueEnvData`，深度 1）
传感器任务是唯一的生产者，用 `xQueueOverwrite` 写入；另外三个任务都是消费者，用 `xQueuePeek` 读。深度设成 1 是因为环境数据只关心"最新值"，旧帧没有保留价值；用覆盖写还能保证生产者永远不会因为队列满而阻塞，不会拖慢采集。

**互斥量**（`g_xMutexOLED`）
OLED 会被显示任务和报警任务同时刷，两条写操作交叉会导致屏幕花掉，所以用互斥量把总线访问串行化。这里选互斥量而不是信号量，是因为互斥量带优先级继承：当一个任务正持锁、更高优先级的任务又来申请同一把锁时，持锁任务会被临时抬到相同优先级尽快释放，减少优先级反转带来的延迟，信号量没有所有者概念，做不到这一点。

**软件定时器**（`g_xTimerAlarm`，500ms 自动重载）
作为报警任务的节拍源，让报警的节奏独立于任务调度，不会因为其它任务忙而漂移。

**任务通知**（`g_xAlarmTaskHandle`）
定时器回调里用 `xTaskNotifyGive` 唤醒报警任务。回调本身运行在定时器守护任务里，不能阻塞，所以里面只做这一件事。任务通知也是 FreeRTOS 里最轻的唤醒方式，只操作任务控制块里的一个计数值，不需要走队列。

数据流大致是这样：

```
EnvSensorTask ──xQueueOverwrite──▶ 队列(深度1) ──xQueuePeek──▶ EnvDisplayTask → OLED
                                              ├──xQueuePeek──▶ EnvAlarmTask  → 蜂鸣器/LED
                                              └──xQueuePeek──▶ EnvUARTTask   → printf 串口
```

## 报警阈值

都定义在 `nwatch/env_monitor.h`，方便统一修改：

| 项目 | 阈值 |
|------|------|
| 高温 | ≥ 35°C |
| 低温 | ≤ 5°C |
| 高湿 | ≥ 80% |
| 低湿 | ≤ 20% |
| 光线过暗 | ADC < 500 |
| 障碍物 | 红外检测到（低电平） |

## 关于去抖

温度和湿度这类模拟量在阈值附近会来回波动，比如 35.1 / 34.9 / 35.2 这样跳。如果一超标就报警，会在边界反复触发。所以代码里做去抖：同一个异常状态连续出现 3 个周期（3 × 500ms = 1.5 秒）才真正报警，恢复正常也一样，要连续 3 次正常才解除。

障碍物是个例外。红外输出是 0/1 的二值信号，不存在"边界抖动"，而且要求即时响应——手快速挡一下就该报警，如果也等 1.5 秒，手拿开了才触发就没意义了。所以障碍物单独处理，一检测到就直接置为已达去抖次数，立即报警。

## OLED 显示

屏幕是 128×64 的页地址模式，共 8 页（0~7）。工程里用的是 16px 高的字体，一个字符占 2 页，所以整屏只能放 4 行，且行坐标必须是偶数页（0 / 2 / 4 / 6）。如果用了奇数页，字符会从半页处开始画，和相邻行叠在一起变成乱码。每行最多 16 个字符（128 / 8）。

| 行 | 页 | 显示内容 |
|----|----|----------|
| 1 | 0 | `T:25'C H:65%` 温湿度，无效时显示 `--` |
| 2 | 2 | `L:1023 Obst:Y` 光照值 + 有无障碍 |
| 3 | 4 | `Dist:120cm` 超声波距离，无效时显示 `--` |
| 4 | 6 | `Status: Normal` 当前系统状态 |

状态行的文本对照：

```
Normal          正常
TEMP HIGH!!     高温      TEMP LOW!!      低温
HUMI HIGH!!     高湿      HUMI LOW!!      低湿
LIGHT DARK      光线过暗
OBSTACLE!!      检测到障碍物
```

## 串口输出

正常情况每 3 秒发一帧：

```
[ENV] T:25,H:65,L:1023,D:120,O:1,status=0
```

字段依次是温度、湿度、光照 ADC 值、距离(cm)、障碍物(0=有, 1=无)、当前状态。温湿度读取失败时为 -999。

状态发生跳变时额外发一条报警帧，以及恢复正常时的提示：

```
[ENV][ALARM] status=6 temp=25 hum=65 light=2632 dist=11 obst=0
[ENV][ALARM] back to normal
```

`status` 的取值：0 正常，1 高温，2 低温，3 高湿，4 低湿，5 光线过暗，6 障碍物。

DHT11 连续 3 次读取失败会输出：

```
[ENV] DHT11 read fail (3 tries)
```

## 开发中踩过的坑

挑几个当时 debug 花了些时间的问题记一下。

**串口一直在刷屏、卡死。** 原因是 `vApplicationIdleHook` 里调用了 `vTaskGetRunTimeStats` 并 printf 打印任务统计表。空闲钩子在 CPU 空闲时就会触发，等于只要有空就打印一次，很快把串口灌满。改成空实现就好了。这件事的教训是别在空闲钩子里做实时打印。

**串口固定上报的任务一直不输出。** 查下来是 `xTaskCreate` 创建任务失败了但没检查返回值。当时 `configTOTAL_HEAP_SIZE` 只有 8000 字节，4 个任务栈加上各种 TCB、队列、定时器早就超了，创建到后面的任务时堆耗尽，静默失败。把堆调到 12000 并给每个 `xTaskCreate` 加了返回值检查后正常。FreeRTOS 里创建任务和队列都应该检查返回值，因为它失败时是不报错的。

顺带一提，堆也不是越大越好。这个芯片只有 20KB RAM，我把堆加到 14000 时链接直接报 `L6406E: No space in execution regions` 溢出了，最后停在 12000。

**有障碍物，屏幕却显示 Normal。** 最初的 `EvaluateStatus` 是这样写的：温度无效就 `return SYS_NORMAL`。DHT11 读失败时温度是 -999，于是直接返回了正常，后面的障碍物检测全被跳过。改成每个传感器独立判断、一个失败不影响其它之后解决。这种"提前返回把后面的判断短路掉"的写法不容易发现。

**光照数值反直觉。** 光越强读数反而越小。看电路才明白是光敏电阻加分压：光越强电阻越小，ADC 采到的电压越低。代码里做了 `4095 - raw` 反转，让"光越强数值越大"。

**屏幕乱码。** 一开始用了奇数页坐标，字符跨半页和相邻行重叠。改成偶数页 0/2/4/6 就好了。

**蜂鸣器一上电就响。** 低电平有效，GPIO 初始化后默认低电平，初始化完主动关一下就行。
